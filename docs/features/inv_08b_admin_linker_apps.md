### Tool 1: Bulk Download Text - `modtools/components/BulkDownloadText.jsx:1-189`
- Inputs: Index Title Pattern (regex), Version Title Pattern (regex), Language select (Hebrew & English / he / en), File Format select (Text with tags `txt`, Text without tags `plain.txt`, CSV, JSON). Download enabled only when format AND (title pattern OR version title pattern) set (:122-124).
- Builds relative link `download/bulk/versions/?format=&title_pattern=&version_title_pattern=&language=` (:112-120) -> `GET /download/bulk/versions/` (`urls_library.py:~97`; `sefaria/views.py:1704-1747` `bulk_download_versions_api`, staff only). Server: Mongo `$regex` on `title`/`versionTitle`, `language` equality over `VersionSet`; errors as JSON ("A value is required for 'format'", "No versions found to match query"); zips every matching version file named `"{title} - {lang} - {versionTitle}.{format}"` via `_get_text_version_file` (1750-1793) and returns `application/zip` attachment named `<alnum patterns>-<lang>-<format>.zip`. Copyrighted versions refuse to export ("Cowardly refusing to export copyrighted text") - an assert, which would abort the whole zip.
- Help text covers pattern matching, formats, use cases.

### Tool 2: Bulk Upload CSV - `modtools/components/BulkUploadCSV.jsx:1-311`
- File input (multiple). On Upload: client reads each file (FileReader), `splitCsvByIndex()` (utils/splitCsvByIndex.js:68-145) detects two layouts - "single" (5 header rows: Index Title, Version Title, Language, Version Source, Version Notes in col 1/2, then `[ref,text]` rows) vs "multi" (4 header rows starting with "Version Title"; rows span many books). Multi files are fanned out client-side with `Sefaria.parseRef` into one single-index CSV Blob per book via PapaParse (unresolved refs reported, skipped). Fatal PapaParse quote/delimiter errors abort file.
- Each job POSTed sequentially: `POST /api/text-upload` with `texts[]` file + `defer_toc_refresh=1`, CSRF header (:118-127). Progress message "Uploading i/N: <index>". After all, one `GET /admin/reset/toc` rebuild (:213) unless failed; summary shows uploaded/failed counts, unresolved refs sample, file errors, ToC failure hint.
- Server: `sefaria/views.py:1796-1815` `text_upload_api` (staff) -> `sefaria.export.import_versions_from_stream(f, [1], uid, skip_toc_refresh)`.

### How it works (pipeline)
1. Take page text with Mozilla Readability on a clone of the document (tables and `<sup>` removed), serializer inserts newlines at non-contiguous-prose elements; sanitize with DOMPurify -> text (`getReadableText` :97-103); add whitelist selector text not already covered (:21-29).
2. POST `${sefariaUrl}/api/find-refs?with_text=<1 if popup mode>&debug=<0|1>&max_segments=20` with JSON `{text:{title, body}, metaDataForTracking:{url (canonical unless dynamic), description (meta/og/twitter description), title}, version_preferences_by_corpus}` (:388-423, :468-476). Server returns 202 `{task_id}` (async Celery task), client polls `GET /api/async/<task_id>` with p-retry (15 retries, 500ms..5s, factor 1.5, 120s cap) until SUCCESS (:446-466).
3. For each result in `title` and `body`: `wrapRef` (:275-306) locates the citation text in the DOM using `findAndReplaceDOMText`, disambiguating repeated strings by expanding context up to 10 words (both/before/after; "unique enough" if > 30 chars, tolerance 5 chars) and wraps in `<a class="sefaria-ref" target=_blank href=<sefariaUrl>/<url> data-ref data-result-index data-result-key aria-controls="sefaria-popup">` with `all: unset` inline styles so host CSS can't change look. Skips failed links and ambiguous (>1 refs) unless debug. Excluder (`excluder.js`): never link text already within `<a>`, and honors `excludeFromLinking`; tracking exclusion hook exists but unused (TODO).
4. After wrapping, `bindRefClickHandlers` sets `href = <base>/<url>?lang=<xx>&utm_source=<host>&utm_medium=sefaria_linker` (popup.js:406-425) and wires hover/click popups.
5. Tracking is server-side: the find-refs metadata (url/description/title/refs) is stored as a `WebPage` (`helper/linker/linker.py` `_save_webpage_from_linker_metadata`, `_add_webpage_hit_for_url`); these WebPages feed the "Web Pages" sidebar in the reader (`api/related/<ref>/websites`) and the `WebSite` collection (domains, whitelist_selectors, exclude_from_tracking). Respects nothing client-side about `noindex` in v3 (v2's `_trackPage` skipped pages with `robots noindex`, v2:616-618).
