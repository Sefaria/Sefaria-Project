# devportal: the developer portal (developers.sefaria.org)

> Sources: `devportal/` (Django app), `devportal-ui/` (Vite + React 19 + TypeScript package), `sefaria/urls_developers.py`, `e2e-tests/developers*/`, `docs/dev-portal/` (plan, decisions, research)

## Purpose

Serves developers.sefaria.org from Sefaria-Project instead of ReadMe.io: the homepage, Markdown docs, the interactive OpenAPI reference with Try It, search, the agent surface (`.md` pages, `llms.txt`, `.well-known`, an MCP server), the Powered by Sefaria gallery under `/powered-by`, and a staff editor. The plan and every product decision are in `docs/dev-portal/PLAN.md` and `docs/dev-portal/DECISIONS.md`. Rule when sources disagree: the live ReadMe site wins, except for the deviations registered in `e2e-tests/developers-visual/deviations.ts`.

## How it is wired

- **Third host.** `DEVELOPERS_MODULE = "developers"` (`sefaria/constants/model.py`); `sefaria/hosts.py` builds one django-hosts host per configured module; the developers host uses `sefaria/urls_developers.py`, which includes only `devportal.urls`, `/api/powered-by` and health views. Helm adds the host through `domains.modules` (sandboxes get it from the chart defaults; staging, preprod and prod override modules and need it added).
- **Module quarantine.** No main-site view is reachable on the developers host, and the React 16 app never sees the module: `reader/views.py` passes only `library`/`voices` in `domainModules`, plus `developersURL` and `poweredByURL` props. Portal templates render with `render_to_string` and no request context processors. `devportal/tests/module_quarantine_test.py` pins this.
- **Middleware.** `devportal.middleware.DevportalMiddleware` acts only on developers-host requests: English, the CSP with a per-request nonce (`devportal/security/csp.py`), the agent `Link` headers, 404 logging.
- **Rendering (option A1).** Django renders real HTML for every page (Markdown via `devportal/markdown/`, endpoint articles from files Vite prerenders at build time); the `devportal-ui` bundle then takes over with `createRoot` and adopts the server's body nodes, so nothing re-renders or moves. Page data travels in the `#dp-data` JSON island and `/_portal/page.json`.
- **Build.** `devportal-ui` has its own `package.json`; `build/web/Dockerfile` builds it in a `node:22` stage into `static/bundles/devportal/`. The main site's webpack/React 16 are untouched.

| -------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Models         | `devportal/models/`                                                                 | `Page` (one row per tree node, incl. endpoint pages keyed by `operation_id`) and immutable `PageRevision`; overlay fields for endpoints never write to `docs/openAPI.json`. Migrations are additive only: every sandbox migrates the shared dev database. |
| Markdown       | `devportal/markdown/`                                                               | Pure Python (markdown-it-py + nh3). Dialect and exact output HTML are contract C4 (`devportal/contracts/DIALECT.md`, goldens). `<HTMLBlock>` renders in a sandboxed frame (`/_portal/htmlblock/<revision-pk>/<n>`).                                       |
| Spec           | `devportal/spec/`                                                                   | Pure Python. Title = operation summary, else path-item summary; description = operation description only; per-path slices equal live's `.md`. `devportal_sync_spec` follows spec changes.                                                                 |
| Content import | `devportal/services/seed.py`, `devportal/migration_source/`                         | The vendored `Sefaria/developer-docs` snapshot is imported on `post_migrate` when it changes (`DEVPORTAL_AUTO_SEED`); pages edited in the editor are kept on re-import. Link fixes are data in `link_fixes.yaml`.                                         |
| Publish        | `devportal/services/publish.py`                                                     | Renders, caches HTML/TOC/search text on the revision, rebuilds artifacts (sidebars, sitemap, search documents, llms files) through a builder registry; Celery when enabled, inline otherwise.                                                             |
| Agent surface  | `devportal/views/machine.py`, `devportal/services/{md_export,llms}.py`              | `<path>.md` and `Accept: text/markdown`; three `llms.txt` files byte-equal to live, plus `llms-full.txt`.                                                                                                                                                 |
| MCP            | `devportal/mcp/`                                                                    | Hand-written streamable-HTTP JSON-RPC server (WSGI). `execute-request` is locked to `DEVPORTAL_API_ORIGIN` and the spec's paths/methods, sends no cookies, follows no redirects, is rate limited. Owner: see `devportal/mcp/README.md`.                   |
| Editor         | `devportal/views/editor_api.py`, `devportal-ui/src/editor/`                         | Staff only (`staff_api`, CSRF). TipTap with a source-preserving serializer: unedited blocks keep their exact bytes (round-trip tests over all 152 imported files).                                                                                        |
| Try It         | `devportal-ui/src/reference/tryit/send.ts`                                          | Browser calls the API origin directly with `credentials: 'omit'` (the parent domain's session cookies must never ride along); responses are shown as text. A public demo key path exists but is off (`DEVPORTAL_DEMO_API_KEY`).                           |
| Gallery        | `devportal-ui/src/gallery/`, `devportal/views/gallery.py`                           | Moved from `Sefaria/powered-by`; reads `/api/powered-by` same-origin. `/powered-by` on sefaria.org moves here only when `DEVPORTAL_CUTOVER_DONE` is true.                                                                                                 |
| Settings       | `sefaria/settings.py` (`DEVPORTAL_*`), contract `devportal/contracts/settings.json` | `DEVPORTAL_TRUST_GATEWAY_CLIENT_IP` must only be true behind the gateway (Helm sets it from `gateway.enabled`).                                                                                                                                           |

## Tests

- `devportal/tests/pure/` run without Django (`-p no:django`); `devportal/tests/` run on `--ds=devportal.dev.settings_standalone` (SQLite, no Mongo), which is how CI runs them (the `devportal-django` job in `.github/workflows/continuous.yaml`). Both need `-p no:sefaria_conftest`: the root `conftest.py` otherwise loads `sefaria/conftest.py`, which needs Django and MongoDB.
- `devportal-ui`: Vitest (`npm test`), type check, ESLint, Stylelint, Prettier.
- Playwright: `e2e-tests/developers/` (DEV-* IDs, page objects in `e2e-tests/pages/developers/`), registered only when the developers host is known (`E2E_DEVELOPERS_URL`). Visual parity: `playwright.devportal-visual.config.ts` against baselines captured from live in `e2e-tests/developers-visual/baselines/`.
- Local server: `python manage.py migrate --settings=devportal.dev.settings_standalone` (imports all content), `npm run build` in `devportal-ui`, copy `devportal-ui/dist` to `static/bundles/devportal`, then `runserver` with the same settings.
