# The future Sefaria reader — product and architecture specification

This folder is the living specification for the next Sefaria reader. It is written and kept current by **Claude Tag** in the Slack
channel **#reader-future**, from the team's conversation there, with the skill **`capture-future-spec`**. People steer the
conversation area by area; Claude records what is said against the right area, checks architecture claims against the code, and
proposes every change as a pull request to the `reader-next` branch.

It compares two clients that live on this repository:

| | Where | What it is |
|---|---|---|
| **Legacy client** | `master` branch: `static/js/`, `reader/`, `templates/` | The React 16 + Django client serving www.sefaria.org today |
| **New client** | `reader-next` branch: `reader-next/` | The React 19 + TanStack Start rebuild, served from the node pods on the `reader-next` cauldron |

The two are audited feature by feature in the **Feature Atlas** (`reader-next/docs/features/`: 945 features in 29 product areas),
which this specification is organised by.

## How it is organised

- **One folder per product area** (the atlas's 29), each with `product.md` (what readers get) and `architecture.md` (how it is built).
  - The sections at the top belong to the channel: summary, target, changes from today, open questions, decisions.
  - The **BASELINE** block at the bottom is generated from the atlas by `tools/seed.py`: what sefaria.org does today, where each
    client implements it, and the gaps. Re-running the script refreshes only that block.
- **`DECISIONS.md`**: every decision, dated, with its area, who decided, and a link to the Slack message.
- **`CROSS_CUTTING.md`**: what spans many areas (design system, performance, accessibility, data layer, rollout) or does not fit one.
- **`SETUP.md`**: how Claude Tag is set up for the channel (admin steps, channel instructions, memory, routines).
- **`claude-tag/`**: the `capture-future-spec` skill, packaged as a plugin.

## How the channel works

- **Steer by area.** Start a thread per area when you want to focus ("Focus: Search & autocomplete"); talk freely anywhere else.
  Claude places every message in the area(s) it is about, whether or not it names one.
- **`[area]` tags are optional** (`[search]`, `[connections]`): they help, they are not required.
- **`Decision:`** at the start of a message marks a decision. It goes to `DECISIONS.md` and the area's Decisions section.
- **`@Claude capture`** records a thread now, instead of waiting for the evening digest.
- **Every evening** Claude reads the day's messages, updates the affected areas and opens (or refreshes) one pull request,
  `spec digest YYYY-MM-DD`, then posts what changed. **Every week** it runs a consistency pass and suggests the next focus area.
- Statuses on every item: **idea · proposed · agreed · decided**. Only a `Decision:` makes something decided, and a decided item
  changes only by a new decision.
